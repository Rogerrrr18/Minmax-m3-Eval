§ 02-A Coding 场景

Coding 评测基准详解

Coding 场景选用 6 个覆盖代码生成、补全、修复、优化、SQL 与算法的主流开源基准，从不同角度评估模型的编程能力。

🧪 HumanEval by OpenAI
大模型代码能力的"鼻祖"基准。164道Python编程题，每题包含函数签名、文档字符串和标准答案，考察模型根据需求生成完整代码的能力。
题数 164 语言 Python 指标 Pass@1
🧪 MBPP by Google
974道Python编程题，题目更贴近日常编程场景，涵盖数据结构、字符串处理、文件操作等，难度略低于HumanEval，覆盖面更广。
题数 974 语言 Python 指标 Pass@1
🌐 LiveCodeBench 持续更新
从Codeforces、LeetCode等平台实时抓取新题目，避免数据污染。测试集不断更新，真正考验模型的实时推理能力，而非记忆能力。
题数 ~800 语言 多语言 指标 Pass@1
🏢 BigCodeBench 开源社区
1140道高质量编程题，难度显著高于HumanEval，覆盖真实项目场景（如文件处理、API调用、数据序列化等），更接近实际工程需求。
题数 1140 语言 多语言 指标 Pass@1
🗄️ Spider Text-to-SQL
Text-to-SQL 领域的标杆基准。将自然语言问题转换为 SQL 查询，涵盖 200+ 数据库 schema，是检验模型数据库查询能力的核心基准。
题数 ~7000 语言 SQL 指标 EX/ES
⚙️ CRUXEval 代码执行
要求模型不仅生成代码，还需预测代码执行结果（输入→输出）。考察模型对代码语义和运行时行为的理解深度。
题数 800 语言 多语言 指标 Acc

§ 04 案例库

Good Case / Bad Case 示例

每个维度均选取具有代表性的 Good Case（模型正确或优秀完成）和 Bad Case（模型失败或有明显缺陷），辅助理解能力分布。

💻 Coding 案例

📝 代码生成 — Good Case

✅ Good Case
维度：代码生成 | 基准：HumanEval | 难度：中等
【题目】写一个函数，接受一个整数列表，返回其中所有奇数的和。例如输入 [1,2,3,4,5]，返回 9。
def sum_of_odds(nums): return sum(x for x in nums if x % 2 != 0) # 测试 print(sum_of_odds([1,2,3,4,5])) # 输出: 9 print(sum_of_odds([2,4,6])) # 输出: 0
✅ 评测结论：代码简洁、正确，使用生成器表达式，逻辑无懈可击。通过 HumanEval 标准评测。

📝 代码生成 — Bad Case

❌ Bad Case
维度：代码生成 | 基准：HumanEval | 难度：较难
【题目】实现一个 LRU Cache，支持 get(key) 和 put(key, value) 操作，要求 O(1) 时间复杂度。
class LRUCache: def __init__(self, capacity): self.capacity = capacity self.cache = {} def get(self, key): if key in self.cache: return self.cache[key] return -1 def put(self, key, value): if key in self.cache: self.cache[key] = value else: if len(self.cache) >= self.capacity: # 错误：应该删除最久未使用的，这里直接删了第一个 self.cache.pop(next(iter(self.cache))) self.cache[key] = value # 问题：get操作后没有更新访问顺序，LRU语义完全错误
❌ 评测结论：代码逻辑错误，LRU 语义要求 get 后该 key 应移到最后，但代码未实现。复杂度也非 O(1)。未通过 BigCodeBench 标准评测。

🔧 错误修复 — Good Case

✅ Good Case
维度：错误修复 | 基准：BigCodeBench修复集
【题目】以下代码有Bug：统计列表中出现次数最多的元素，如有多个则返回任意一个。
def most_frequent(lst): if not lst: return None counts = {} for item in lst: counts[item] = counts.get(item, 0) + 1 max_count = max(counts.values()) # ✅ 正确遍历找到第一个max_count的key，而非.pop last for k, v in counts.items(): if v == max_count: return k return None # 测试 print(most_frequent([1,3,2,1,3,3])) # 正确返回 3 print(most_frequent([])) # 正确返回 None
✅ 评测结论：正确处理空列表边界条件，遍历逻辑清晰，返回了出现次数最多的元素。通过 BigCodeBench 修复评测。

🔧 错误修复 — Bad Case

❌ Bad Case
维度：错误修复 | 基准：BigCodeBench修复集
【题目】二分查找函数，当target不存在时返回-1，但代码返回了错误的索引。
def binary_search(arr, target): left, right = 0, len(arr) - 1 while left <= right: mid = (left + right) // 2 if arr[mid] == target: return mid # ✅ 找到了 elif arr[mid] < target: left = mid + 1 else: right = mid - 1 return -1 # ⚠️ 看起来正确，但当数组含重复元素时， # 返回的索引不一定是第一个匹配的位置 # 如果题目要求返回第一个匹配，而原代码返回任意匹配位置，则未修复
⚠️ 评测结论：在简单场景下正确，但未满足「返回第一个匹配位置」的语义要求，在有重复元素的边界情况下失败。

🗄️ SQL查询 — Good Case

✅ Good Case
维度：SQL查询 | 基准：Spider
【题目】查出每个部门平均工资高于公司平均工资的部门名称和平均工资。
SELECT department_name, AVG(salary) AS avg_salary FROM employees e JOIN departments d ON e.department_id = d.department_id GROUP BY e.department_id, d.department_name HAVING AVG(salary) > (SELECT AVG(salary) FROM employees)
✅ 评测结论：SQL语法正确，JOIN、HAVING、子查询使用准确，返回结果与Spider标准答案一致。

🗄️ SQL查询 — Bad Case

❌ Bad Case
维度：SQL查询 | 基准：Spider（复杂JOIN）
【题目】查询所有订单，客户需按国家分组，计算每个国家的订单总量和平均订单金额。
SELECT c.country, COUNT(o.order_id) AS total_orders, AVG(o.order_amount) AS avg_amount FROM orders o JOIN customers c ON o.customer_id = c.customer_id # ❌ 缺少 GROUP BY country，SQL语法错误 ORDER BY c.country # 或者返回了未分组的数据，无法正确统计
❌ 评测结论：缺少 GROUP BY 子句，导致语法错误或数据未正确聚合。在 Spider 评测中得 0 分。
