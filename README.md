# MiniMax-m3 科学评测 v3.1

> 四模型 × 十一维度 × 640 题 · 三裁判交叉验证 · 0-10 分制

---

## 📖 项目介绍

这是一个面向中文大语言模型的**科学横向评测项目**，核心目标是：

1. **客观评估 MiniMax-m3 的真实能力水平**
2. **与 deepseek-v4、mimo-v2.5、kimi-k2.6 等主流模型进行同场对比**
3. **建立可复现、可对比、覆盖全面的中文大模型能力基准**

本项目采用**三裁判交叉验证**机制（GPT-5.5 + deepseek-v4-flash + MiniMax-m3 自身），有效消除单一裁判的评分偏见，使结论更具可信度。

---

## 🎯 评测意图

市面上的模型宣传往往侧重单一维度（如代码能力或对话能力），而真实业务场景需要模型同时具备：

- **编程开发**：写代码、补全代码、修 bug、做优化
- **数据分析**：写 SQL、做表格处理
- **逻辑推理**：解数学题、算法设计
- **办公协作**：写文档、处理邮件、信息抽取
- **多语言理解**：中英文混合场景下的语义判断

本评测围绕这些真实场景设计，避免"刷榜式"评测，更关注模型在**综合办公 + 代码开发**场景下的实际可用性。

## 🧪 评测方法

整个评测分为 5 个阶段：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ 1. 数据准备  │ -> │ 2. 模型调用  │ -> │ 3. 自动验证  │ -> │ 4. 多裁判评分│ -> │ 5. 交叉合并  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

### 阶段 1：数据集准备

从官方/学术数据集加载题目，对缺失维度通过代码注入、NER 构造、办公场景设计等方式补全。最终形成 **11 个维度、640 道题** 的测试集。

| 维度 | 题目数 | 数据来源 |
|------|--------|----------|
| 代码生成 | 100 | HumanEval 30 + MBPP 40 + BigCodeBench 30 |
| SQL 查询 | 50 | Spider |
| 算法能力 | 80 | GSM8K 50 + MBPP-Algo 30 |
| 代码补全 | 50 | CodeSearchNet |
| 错误修复 | 60 | 自建-BugFix（向正确代码注入常见 bug） |
| 代码优化 | 50 | 自建-Optimize 30 + BigCodeBench-Opt 20 |
| 多语言办公 | 50 | PAWS-X |
| 信息抽取 | 50 | 自建-NER（覆盖科技、金融、医疗、体育等领域） |
| 文档撰写 | 50 | XSum 30 + CCE 20 |
| 邮件处理 | 50 | 邮件评测集 15 + 自建 35 |
| 表格处理 | 50 | 格物评测集 5 + 自建 45 |

### 阶段 2：模型调用

4 个模型分别独立完成全部 640 题：

- **MiniMax-m3**：官方 API（https://api.minimax.chat/v1）
- **deepseek-v4-flash**：通过 opcrouter 代理
- **mimo-v2.5-pro**：通过 opcrouter 代理
- **kimi-k2.6**：通过 opcrouter 代理

调用参数：
- 代码类任务 `max_tokens = 4096`
- 办公/NLP 类任务 `max_tokens = 2048`
- 启用 3 次指数退避重试
- 自动过滤 `<think>` 等思考标签
- 每维度实时保存 checkpoint，支持断点续跑

### 阶段 3：自动验证

对代码/SQL/算法类任务做轻量级规则检查：

- 输出是否为空或 API 错误
- 输出是否被截断
- 是否包含有效的代码/SQL 结构

输出 **0-3 分** 的基础分，作为裁判评分的参考。

### 阶段 4：三裁判独立评分

这是评测的核心环节。每个维度由 **3 个独立裁判模型** 分别评分：

- **GPT-5.5**：通用能力最强的外部裁判
- **deepseek-v4-flash**：基线对照模型兼任裁判
- **MiniMax-m3**：被测模型自身也参与裁判（消除外部裁判的品牌偏见）

评分规则：
- 裁判**不知道**输出对应哪个模型（盲评）
- 每个维度有专门的评分标准
- 输出 **0-10 分** 和简短评分理由

### 阶段 5：交叉合并

将 3 个裁判的评分取平均，生成最终得分。如果某裁判对某模型的评分系统性偏高/偏低，交叉验证机制会自动稀释这种偏见。

## 🚀 如何复现评测

### 环境要求

- Node.js >= 18（需要原生 `fetch`）
- Windows / macOS / Linux 均可

### 1. 克隆项目

```bash
git clone https://github.com/Rogerrrr18/Minmax-m3-Eval.git
cd Minmax-m3-Eval
```

### 2. 运行完整评测

```bash
cd 04-scripts
node run_all.js
```

这会依次执行：模型调用 -> 自动验证 -> GPT 裁判评分 -> 生成报告。

**注意**：完整跑完需要约 5-6 小时（模型调用 ~4 小时 + 裁判评分 ~2 小时）。

### 3. 只跑单个阶段

```bash
# 只跑模型调用
node eval_v3.js

# 只跑自动验证
node auto_validator.js

# 只跑三裁判评分
node judge_multi.js

# 合并裁判结果
node merge_judges.js

# 只生成报告
node report_v3.js

# 只生成 HTML 研报
node generate_report_html.js
```

### 4. 并行跑多个模型（加速）

```bash
# 分别启动 4 个模型（可并行）
node eval_v3_single.js MiniMax-m3
node eval_v3_single.js deepseek-v4-flash
node eval_v3_single.js mimo-v2.5-pro
node eval_v3_single.js kimi-k2.6
```

每个模型跑完后会自动保存 checkpoint，支持断点续跑。

## 📊 结果解读

评测完成后，最重要的文件是：

| 文件 | 内容 | 用途 |
|------|------|------|
| `eval_report_v3_1_merged.html` | 完整 HTML 研报（v3.1 三裁判） | 直接浏览器打开查看 |
| `eval_report_merged.json` | 结构化合并数据 | 用于二次分析或可视化 |
| `judgments_merged.json` | 三裁判合并评分 | 审计每条评分的来源 |

### 如何看懂得分

- **综合得分**：模型在 640 题上的三裁判平均分（满分 10 分）
- **维度得分**：该维度所有题目的三裁判平均分
- **健康率**：非空且未被截断的输出比例
- **低分数量**：得分 ≤3 的题目数量，反映"硬伤"数量

### 当前最佳结果（v3.1 三裁判交叉验证）

| 排名 | 模型 | 综合得分 |
|------|------|----------|
| 1 | mimo-v2.5-pro | **7.83/10** |
| 2 | deepseek-v4-flash | **7.76/10** |
| 3 | **MiniMax-m3** | **7.63/10** |
| 4 | kimi-k2.6 | **7.40/10** |

> **重要修正**：v3.0 单 GPT-5.5 裁判时排名为 deepseek（7.92）> mimo（7.83）> MiniMax（7.82）。引入三裁判后，deepseek 被下调 0.16 分，MiniMax 被下调 0.19 分，mimo 保持不变。**这揭示了单一外部裁判对国产模型存在评分宽松倾向**。

### MiniMax-m3 维度表现（v3.1）

| 维度 | 得分 | 四模型排名 |
|------|------|------------|
| 算法能力 | 9.18 | 第 2 |

| 信息抽取 | 8.64 | 第 3 |
| 代码生成 | 8.37 | 第 3 |
| SQL 查询 | 8.26 | 第 3 |
| 多语言办公 | 8.31 | 第 4 |

## 🔧 常见问题

**Q：为什么代码补全维度全模型得分都很低？**  
A：当前 prompt 要求模型"补全缺失代码"，但模型往往输出完整函数。这是一个测试方式设计问题，后续版本会优化。

**Q：为什么 SQL 查询得分普遍不高？**  
A：Spider 数据集包含多表 JOIN、聚合、子查询等复杂场景，对 schema 理解要求较高。

**Q：三裁判结果和单裁判差别大吗？**  
A：非常大。v3.0 单 GPT-5.5 裁判让 deepseek 排第一，但三裁判验证后 mimo 才是第一，且 MiniMax 与 mimo 的真实差距从 0.01 分扩大到 0.20 分。

**Q：如何添加新模型进行对比？**  
A：在 `eval_v3.js` 或 `eval_v3_single.js` 的 `MODELS` 数组中添加模型配置即可。新模型也可兼任裁判，进一步丰富交叉验证。
